# تدقيق واجهة المشروع الأصلي وتطبيقها في Peche TN 1.1.0

## المرجع الذي تمت مراجعته

تمت مراجعة واجهة المشروع الأصلي في تاريخ Git للمستودع، خصوصاً:

- `d14a1ad:frontend/index.html` و`d14a1ad:backend/main.py`؛
- النسخة اللاحقة `d437223:frontend/index.html` التي أضافت تبويب مسح الشواطئ.

الواجهة الأصلية كانت رحلة تطبيق مباشرة: عنوان، تبويب «تقرير بقعة»، خريطة كبيرة، إعدادات الموقع في بطاقة جانبية، اختيار اليوم، زر واحد لتوليد التقرير، ثم تقرير نصي مع النسخ والتنزيل/المشاركة.

## ما احتفظ به الإصدار الجديد

1. التطبيق يبدأ مباشرة من «تقرير بقعة» بدل صفحة تسويق طويلة.
2. الخريطة مفتوحة افتراضياً وإعدادات الموقع واليوم واتجاه البحر أمام المستخدم في مساحة عمل واحدة.
3. يوجد زر أساسي واحد يولّد القرار والتقرير معاً.
4. التقرير يفتح تلقائياً بعد نجاح التحليل.
5. إجراءات التقرير تشمل النسخ وTXT والطباعة/PDF وواتساب.
6. بقي اتجاه البحر قابلاً للتعديل اليدوي، مع حساب Overpass آلي ومصدر ومسافة ومماس ونصف قطر وثقة ظاهرة.

## ما لم يُنسخ لأنه غير موثوق أو غير مكتمل

- لم يُنسخ تبويب «مسح الشواطئ» الوهمي أو غير المكتمل كواجهة توحي بميزة غير موجودة.
- لم يعد المتصفح يجلب Open-Meteo ثم يرسل الخام إلى خادم آخر؛ الخادم يجلب البيانات ويثبت المصدر والزمن.
- لا يوجد مفتاح Gemini عام في الخادم أو المستودع. مفتاح المستخدم اختياري ويُحفظ في `localStorage` بعد موافقة صريحة فقط.
- أزيلت «نسبة النجاح» الوهمية، مواقيت المد القمرية المصطنعة، السولونار المرجّح بلا تحقق، ومسافة الرمي أو وزن الرصاص المخترعان.
- لا يقرر Gemini. المحرك الحتمي ينتج القرار والأرقام وEvidence Packet؛ Gemini كاتب مقيد فقط.

## بنية التقرير المطور

التقرير الحالي يستعمل كامل ناتج المحرك ويعرض:

- القرار الثنائي وسبب الحسم؛
- السلامة، قابلية التنفيذ، مؤشر الفرصة والثقة كمحاور منفصلة؛
- نوافذ متواصلة موصى بها وفترات يجب تجنبها؛
- نشاط 48–72 ساعة، طاقة الموج، دفع الريح/التيار، المطر والتغطية؛
- احتمالي الصوفة والعكارة وعدد عائلات القرائن التشغيلية المختلفة، مع توضيح أنها ليست أرصاداً أو مصادر مستقلة؛
- التفكيك الزمني والأرقام المرجعية الخام؛
- رصد METAR المنفصل والمسافة عن البقعة؛
- مصدر كل مجموعة بيانات وتاريخ الجلب؛
- سجل العوامل الـ63: مستخدم في القرار، سياق، proxy، Unknown أو مستبعد؛
- تقرير حتمي كامل عند غياب Gemini أو فشله.

## ملاحظة النشر

تعطل 1.0.1 على Vercel كان في بوابة `/api` لا في رفع المستخدم. كان `rewrite` يعيد كل `/api/*` إلى `/api`، بينما `/api` نفسه يطابق القاعدة مرة أخرى. حاول 1.1.0 استبداله بقواعد `routes/request.path transforms`، لكن الاختبار الحي أثبت أنها تعيد HTML 500 أيضاً رغم نجاح البناء. لذلك أزال 1.2.0 توجيه API المخصص كلياً في مسار Vercel، وأضاف نشر Render كاملاً في Docker واحد كالمسار الإنتاجي الموصى به.
