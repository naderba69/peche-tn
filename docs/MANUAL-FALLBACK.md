# الاحتياط اليدوي عند تعذّر البيانات

الوثيقة تصف ما يحدث عندما لا تتوفر بيانات آلية، وما يفعله الصياد في هذه الحالة. لا توجد في النظام أي استمارة لتسجيل الرحلات، ولا يُطلب من المستخدم إدخال بيانات يدوية لتسجيل رحلة.

## 1. ما يقرره النظام تلقائياً
| الحالة | النتيجة |
|---|---|
| تعذّر جلب الموج أو الريح | `تعذّر التحليل`، ولا يُعطى أي قرار GO |
| تعذّر جلب اتجاه الساحل | يتوقف التحليل |
| نوع الشاطئ مفقود | `حذر` وليس `NO_GO` (التزام a2aa01f) |
| تعذّر Copernicus الاختياري | تبقى القرائن الأخرى، ويظهر أن الجزء اختياري ولم يُستعمل |
| بوابة INM غير متاحة | لا يصدر `GO`؛ يبقى التحليل قابلاً للعرض مع تنبيه |

النظام لا يملأ الفجوات بقيم افتراضية، ولا يبحث جانبياً عن قيمة مشابهة.

## 2. ما يفعله الصياد يدوياً
عند تعذّر النظام، يعتمد الصياد على مصادر رسمية منشورة، ويقرر بنفسه:
1. **نشرة INM** للموج والريح لليوم نفسه.
2. **مشاهدة الشاطئ مباشرة** قبل النزول: الكسرة، وجود قنوات رغوية تتجه نحو البحر، والحطام أو الأعشاب.
3. **جدول المد الرسمي** للميناء الأقرب.
4. **إن تعذّر كل ما سبق**: لا يُنزل الصياد الرصاص الثقيل ولا يبدأ الصيد في القناة، ويُعتبر اليوم غير آمن.

## 3. القاعدة الحاكمة
- عدم اليقين لا يساوي `GO`. أي غياب بيانات يبقى `حذر` أو `تعذّر التحليل`.
- الاحتياط اليدوي قرار شخصي من الصياد، وليس مدخلاً يضعه النظام كحقيقة.
- لا يُستعمل الاحتياط اليدوي لإرسال بيانات الرحلات إلى النظام.

## 4. ما لم يُنفّذ بعد
- ربط مؤشرات INM بواجهة المستخدم كرابط مباشر. مُؤجَّل لأنه يحتاج تحقق من صيغة الصفحة الحالية.
- أي تسجيل آلي للرحلات. لا يُبنى بدون طلب صريح، لأن المستخدم رفض الإدخال اليدوي للرحلات.
